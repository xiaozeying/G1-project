## 3. 今日最关键结论

### 3.1 本地先验、机器人后接 是正确路线

原因：

- 机器人本机缺少完整推理环境
- 机器人还要与语音、视觉采集、ROS、动作链共享资源
- 更适合作为 `openai_compatible` 消费端，而不是第一站就本机起大视觉模型

### 3.2 Qwen2.5-VL-3B 已完成本地下载，但 8GB 显存仍然不够

今天实际完成：

- `Qwen/Qwen2.5-VL-3B-Instruct` Hugging Face snapshot 已完成本地下载
- 使用本地 snapshot 重启 `vLLM`，排除了“边下载边起服务”的干扰
- 权重加载成功
- 多模态 profile 阶段失败

明确报错：

- `torch.OutOfMemoryError`
- 额外申请约 `160 MiB` 失败
- 日志显示模型本体加载已占约 `7.16 GiB`

结论：

- `Qwen2.5-VL-3B bf16 + vLLM` 对这张 `RTX 4060 8GB` 仍然偏紧
- 这进一步说明：更不能乐观假设它能直接落到机器人本机

## 4. 当前推荐路线

今天收口后的建议优先级：

1. 机器人继续承担：
   - 语音入口
   - 相机采集
   - 安全中间层
   - 动作执行
2. 离线视觉模型优先放在：
   - 本地开发机
   - 或局域网更大显存 GPU 主机
3. `Qwen-VL` 若继续推进，优先尝试：
   - 更小规格
   - 或量化版本
4. 当前稳定基线仍是：
   - `gemma3:latest`
